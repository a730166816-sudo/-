# الدليل المعماري والبرمجي الشامل لنظام إدارة الكتائب العسكرية (BMS Pro Enterprise)

يمثل نظام **BMS Pro (Battalion Management System)** منظومة مؤسسية متكاملة لإدارة الكتائب والوحدات العسكرية وفق معمارية **Clean Architecture** ومبادئ **SOLID**، مع دعم كامل للعمل دون اتصال (**Offline-First**) عبر الويب (**Dexie.js / IndexedDB**) والهواتف الذكية (**Flutter / Hive**) والمزامنة التلقائية مع الخادم المركزي (**Node.js + Express + TypeScript + PostgreSQL + Prisma + Socket.io**).

## 1. المعمارية الموحدة للبيانات والأمان (Unified Enterprise Architecture)

لضمان عدم تضارب البيانات بين تطبيق الويب وتطبيق الهواتف الذكية، يعتمد النظام المعمارية الموحدة التالية:

| الطبقة | التقنيات المعتمدة | الدور الوظيفي والأمني |
| :--- | :--- | :--- |
| **قاعدة البيانات المركزية** | PostgreSQL 16 + Prisma ORM | تخزين مترابط يضم 22 جدولاً مع الفهارس المركبة والمفاتيح الخارجية وسلة المهملات. |
| **الخادم والـ API** | Node.js + Express + TypeScript + Socket.io | واجهات REST موثقة بـ Swagger + بث حي لغرفة العمليات عبر WebSockets + Cron Jobs للنسخ الاحتياطي. |
| **التشفير والحماية** | AES-256-GCM + bcrypt + JWT + 2FA + Helmet | تشفير الحقول العسكرية الحساسة والنسخ الاحتياطية بـ AES-256، وتشفير كلمات المرور بـ bcrypt، وحماية CSRF/XSS/SQLi. |
| **تطبيق الويب (RTL)** | HTML5 + Bootstrap 5 RTL + ES2024 + Dexie.js + Chart.js | لوحة قيادة، غرفة عمليات، تقارير (PDF/Excel/Word/CSV)، ماسح QR، وعمل كامل دون اتصال. |
| **تطبيق الموبايل** | Flutter + Provider + Hive + Firebase FCM | تطبيق ميداني للضباط والأفراد يعتمد Hive للتخزين المحلي دون اتصال وFirebase FCM للإشعارات الفورية. |

## 2. مصفوفة الصلاحيات والأدوار العسكرية (14 دوراً في نظام RBAC)

يدعم النظام 14 دوراً عسكرياً بتدرج هرمي، مع التحقق من الصلاحيات على مستوى كل شاشة وكل نقطة نهاية (Endpoint):

| الدور العسكري | الكود البرمجي | الصلاحيات الأساسية الممنوحة |
| :--- | :--- | :--- |
| **مدير النظام** | `SYS_ADMIN` | صلاحية كاملة على كافة الوحدات والمستخدمين والنسخ الاحتياطي والتدقيق الأمني. |
| **قائد لواء** | `BRIGADE_CMD` | الإشراف الاستراتيجي، اعتماد الإجازات، استعراض كافة التقارير، وغرفة العمليات. |
| **رئيس العمليات** | `OPS_CHIEF` | إدارة غرفة العمليات، المهام القتالية، الجاهزية، الأسلحة، والآليات. |
| **رئيس الأفراد** | `HR_CHIEF` | إدارة شؤون الأفراد، السجل التاريخي، الحضور، الإجازات، والأذونات. |
| **رئيس التدريب** | `TRAINING_CHIEF` | إدارة الدورات التدريبية، اختبارات اللياقة والرماية، وتقييم الكفاءة. |
| **قائد كتيبة** | `BATTALION_CMD` | قيادة الكتيبة، اعتماد الإجازات، إدارة العهدة التسليحية والآليات، والتقارير. |
| **قائد سرية** | `COMPANY_CMD` | إدارة أفراد السرية، التحضير اليومي، رفع واعتماد طلبات السرية، وعهدة السلاح. |
| **قائد فصيل** | `PLATOON_CMD` | متابعة انضباط الفصيل، تنفيذ المهام الميدانية، وتحديث بيانات أفراد الفصيل. |
| **ضابط مناوب** | `DUTY_OFFICER` | إدارة طابور الصباح والمساء، مسح بطاقات QR، وتسجيل بلاغات غرفة العمليات. |
| **ضابط تدريب** | `TRAINING_OFFICER` | رصد درجات الرماية واللياقة البدنية ومتابعة تنفيذ الخطط التدريبية. |
| **ضابط أمن** | `SECURITY_OFFICER` | مراقبة سجل العمليات (Audit Log)، فحص حركة الأسلحة والآليات، والتدقيق الأمني. |
| **ضابط إداري** | `ADMIN_OFFICER` | إعداد الكشوفات الإدارية، متابعة الإمداد والتموين والوقود، وتصدير التقارير. |
| **كاتب** | `CLERK` | إدخال وتحديث بيانات الأفراد والحضور وتجهيز النماذج بدون صلاحية الحذف أو الاعتماد. |
| **جندي** | `SOLDIER` | استعراض بطاقته العسكرية (QR)، رصيد إجازاته، والمهام المسندة إليه فقط. |

## 3. مخطط قاعدة البيانات الكامل (`prisma/schema.prisma`)

يتضمن الملف المرفق في الحزمة البرمجية تعريفاً كاملاً للجداول الـ 22 التالية مع العلاقات والمفاتيح الخارجية:
1. `User`: حسابات المستخدمين، المصادقة الثنائية `twoFactorSecret`، وتجزئة `refreshTokenHash`.
2. `Role`: الأدوار العسكرية الـ 14.
3. `Permission`: الصلاحيات الدقيقة (`canAddPersonnel`, `canEditPersonnel`, `canDeletePersonnel`, `canApproveLeave`, `canViewReports`, `canExportPDF`, `canManageWeapons`, `canManageVehicles`, `canManageUsers`).
4. `Unit`: الهيكل التنظيمي الشجري (`parentId` يدعم: لواء ← كتيبة ← سرية ← فصيل).
5. `Rank`: الرتب العسكرية وأرصدة الإجازات السنوية المعيارية لكل رتبة.
6. `Job`: الوظائف والتخصصات الميدانية.
7. `Personnel`: البيانات الرباعية، الرقم العسكري الفريد `militaryId`، فصيلة الدم، درجة الانضباط، والحالة (`ACTIVE`, `ON_LEAVE`, `ON_MISSION`, `ARCHIVED`, `DISABLED`).
8. `Attendance`: سجلات طابور الصباح والمساء مع قيد فريد `@@unique([personnelId, date, shift])` ودعم `QR_CODE`.
9. `Leave`: الإجازات (اعتيادية، سنوية، مرضية، طارئة) مع خصم الرصيد الآلي وسير الموافقات.
10. `PermissionRequest`: الأذونات الساعية واليومية مع وقت الخروج والعودة.
11. `Weapon`: الأسلحة الفردية والثقيلة بالأرقام التسلسلية وحالة الصيانة والعهدة وسجل الحركة `movementLog`.
12. `Ammunition`: مخزون الذخائر حسب العيار (الوارد، المنصرف، المتبقي، وحد الإنذار الأدنى).
13. `Vehicle`: الآليات والمدرعات والدراجات مع رقم المحرك والشاصي ونسبة الوقود والسائق وسجل الأعطال.
14. `Task`: المهام القتالية والدورات التدريبية واختبارات اللياقة والرماية.
15. `Announcement`: البلاغات والإنذارات الفورية في غرفة العمليات.
16. `Notification`: الإشعارات الفورية الموجهة للمستخدمين عبر Socket.io وFirebase FCM.
17. `Readiness`: قياسات الجاهزية القتالية وحالة الطقس والاستعداد لكل وحدة.
18. `Log`: سجل التدقيق الأمني الشامل (`Audit Log`) لكل حركة في النظام.
19. `History`: السجل التاريخي التراكمي لكل فرد عسكري (ترقيات، تنقلات، أوسمة، جزاءات).
20. `Backup`: سجل النسخ الاحتياطية المشفرة بـ `AES-256-GCM`.
21. `Trash`: سلة المهملات لحفظ السجلات المحذوفة بصيغة `snapshotJson` مع إمكانية الاستعادة الفورية أو الحذف النهائي.
22. `Setting`: إعدادات النظام العامة وشعار الكتيبة.

## 4. خطوات التشغيل والنشر للإنتاج (Production Deployment)

1. **تشغيل قاعدة البيانات والخادم عبر Docker Compose**:
   - انسخ ملف البيئة `.env.example` إلى `.env` وحدد مفاتيح `DATABASE_URL` و`AES_256_SECRET_KEY` و`JWT_ACCESS_SECRET`.
   - نفذ الأمر `npx prisma migrate deploy` لإنشاء الجداول والفهارس في PostgreSQL.
   - شغل الخادم عبر `npm run build && npm start` أو عبر `docker-compose up -d`.
2. **تشغيل الواجهة التفاعلية للويب**:
   - افتح ملف `bms_pro_app.html` مباشرة في المتصفح أو استضفه عبر Nginx؛ يعمل التطبيق فوراً بقاعدة بيانات `Dexie.js` محلية ويدعم التبديل بين الاتصال وعدم الاتصال وتصدير التقارير الـ 42.
3. **تشغيل تطبيق الهواتف الذكية (Flutter)**:
   - داخل مجلد `mobile_flutter`، نفذ `flutter pub get` ثم `flutter run` لتشغيل التطبيق الميداني المزود بمحرك `BmsOfflineSyncEngine` المبني على `Hive`.
